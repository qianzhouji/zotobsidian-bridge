# B4 Execution Report

Date: 2026-11-03

## Scope

B4 adds an independent Reader popup preference (`native` / `bridge`), safe Bridge-to-native transitions, and awaited Reader teardown checkpointing. It does not change the Markdown writer preference (`direct` / `companion`).

## Implemented

- Added a native-default `readerMode` preference and bilingual settings controls with an accessible live status region.
- Connected mode changes to the existing Reader preference observer so open Reader documents reconcile without manual console commands.
- Kept native popup DOM intact beneath the Bridge shell. Bridge mount failures and unavailable cards leave Zotero's native popup available.
- Before switching from Bridge to native, pause new mounts, capture the current textarea value (including an active IME composition), freeze editors, and persist recovery drafts. A checkpoint failure cancels the transition and restores editing.
- Report clean, checkpointed, pending-write, and failed transitions in the settings panel. A pending companion request is not resubmitted by the mode switch.
- During plugin disable/uninstall, await Reader editor checkpoints before removing the adapter DOM and restoring the native popup. Checkpoint failures are written to Zotero's debug log.
- Added automated coverage for two Reader documents, checkpoint aggregation, rollback after a simulated failure, preservation of native comment/color/tag DOM, repeated mode toggles, retry/fail-open behavior, and shutdown restoration.
