## 1. 产品目标与边界

### 1.1 最终操作流程

1. 用户在 Zotero 的 PDF 阅读器中正常创建高亮或下划线批注。
2. 启用 Bridge 模式后，点击一条已经保存的批注，原来的小浮窗位置直接出现 Bridge 卡片，无须再点菜单中的编辑按钮。
3. 卡片加载该批注对应的 Markdown 笔记；尚未建卡时，按需创建并建立稳定关联。
4. 用户直接输入 Markdown，通过“编辑 / 预览”切换查看结果，也可以展开为大窗口。
5. 内容先保存为可恢复的本地草稿，再通过既有写入链路同步；界面明确区分“草稿已保存”“等待同步”“已同步”和“冲突”。
6. 在 Obsidian 中打开的是同一张卡片，不是另一个副本。自动生成的名称采用 `P01N01`，可见的插件属性只保留论文标题。
7. 切回原生模式或停用插件后，Zotero 原生评论界面恢复，原生评论和 Markdown 笔记都不被删除。

**这里替换的是评论区域的交互界面，不是 Zotero 的批注存储系统。** 高亮的位置、颜色、标签、页码与原生批注身份仍由 Zotero 管理。

### 1.3 数据所有权

- Zotero 原生 `annotation.comment` 保持原有含义；Bridge 编辑的是 Markdown 卡片的用户正文，不能把两者视为同一可写字段。
- 原生评论可以作为只读上下文展示，但模式切换不能自动覆盖、清空或反向写入它。今后如需“导入评论为笔记”，须提供明确的独立操作。
- 摘录和论文信息属于来源区；用户输入属于用户区。来源刷新不能覆盖用户区。
- 文件名是可读标识，不是数据库主键。查找依赖完整来源身份和卡片 UUID，不能凭页码、摘录文字或当前列表选中项猜测对应关系。
- `P` 使用 PDF 物理页码，即 `pageIndex + 1`，不采用印刷页码标签；位数至少两位，超过 99 不截断。
- `N` 在同一论文目录、同一物理页码的命名空间内分配。当前实现选取首个可用序号，可能复用空号，但不会为插入新卡片重排已有卡片。
- 同一论文的多个 PDF 当前共享 `Annotations` 目录；底层仍必须保存附件身份。浮窗须在可能混淆时提供附件上下文，不能认为 `P01N01` 自带附件身份。
- 用户手动命名的文件不自动改名。自动名称在来源物理页码改变时是否迁移，在 B0 固定规则并测试；建议本轮保留已有自动名称，明确其为首次分配时的页码，避免扩大自动移动范围。

### 2.3 浮窗接入是独立的技术关卡

Zotero 公开 Reader 事件包含 `renderTextSelectionPopup`、`renderSidebarAnnotationHeader`、`createAnnotationContextMenu` 等。**“选中文本弹出的工具条”与“点击已保存高亮出现的评论浮窗”不是同一个入口。** 公开事件文档没有承诺提供替换后者评论编辑器的接口。

已在隔离 Zotero 10.0.6 中确认：点击已保存高亮会显示 `.annotation-popup`，评论位于 `.comment`，页码/菜单和标签为其他区域。该 popup 属于 `reader._iframeWindow.document`；自然 `renderToolbar` 事件的 `event.doc` 虽然 URL 相同，却是不同 Document。这为局部适配提供线索，但不是稳定插件 API。源码已优先监听 Reader iframe 文档，真实运行时复测仍待完成。

实现优先级：公开扩展点优先；没有合适扩展点时，把版本受控的 DOM 适配集中在一个模块。禁止到处散布私有选择器、全局替换 Reader 方法或改写原生评论保存逻辑。

## 3. 总体架构与执行顺序

```text
已保存批注的点击与浮窗生命周期
    -> ReaderPopupAdapter：识别来源、挂载容器、恢复原生界面
    -> EditorSession：加载、基线、输入状态、草稿、保存与冲突
       -> PopupEditorView：编辑 / 预览 / 展开
       -> WindowEditorView：同一会话的大窗口视图
    -> 既有 CardUpdater / VaultStorage
    -> direct 写入 或 companion 请求队列
    -> Obsidian Vault 应用写入 / 响应 / ACK 收敛
```

`ReaderPopupAdapter`、`EditorSession`、`PopupEditorView` 是建议的职责边界和名称，不表示当前已存在这些模块。具体文件数量服从实现复杂度，不为每一个状态单独增加抽象。

### 3.1 核心约束

1. 一张卡片在 Zotero 侧只有一个受控编辑会话和保存序列；多个视图共享状态，不能成为两个独立写者。
2. DOM 视图被宿主销毁，只解除视图绑定；草稿与在途写入继续由会话服务管理。
3. 每次来源切换使用会话身份和加载代次检查；A 的迟到加载结果不得进入 B 的编辑器。
4. 原生评论区域仅在 Bridge 视图成功挂载、身份验证完成后隐藏；失败立即恢复，不留下空白不可编辑区域。
5. 不全局拦截鼠标和键盘。颜色、标签、页码、菜单、文本选择与 PDF 滚动仍可使用。
6. “已同步”必须对应目标文件的确认结果，不能仅因本地草稿落盘就显示。
7. 关闭浮窗、切模式、停用插件分别处理。正常退出须提交草稿检查点；非正常退出的恢复保证仅涵盖已确认持久化的草稿/请求，不虚称尚未落盘的最后几个按键必然恢复。

## 9A. C 系列：双链补全与只读关联知识卡

本节是用户确认的新功能执行规划，**不是实施完成记录**。C0–C7 的产物、性能数字和测试命令在未实际执行前均不得标记为 PASS。

### 9A.1 产品目标与第一版范围

在 Zotero 阅读文献时，用户可以输入 `[[` 搜索同一配对 Vault 的知识笔记，将标准 Obsidian 双链插入批注正文；点击链接后，在旁边打开目标笔记的只读浮动卡片。子卡内部的链接可继续展开。卡片可拖拽、缩放，卡片头部之间以虚线双箭头呈现关联；根批注卡有小型图标按钮一键收起整个关联组。

| 项目      | 第一版约定                                                                                                                               |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 根卡      | 现有可编辑文献批注卡；仍由 B5 的 EditorSession 保存，不新增写入者                                                                        |
| 子卡      | 同一配对 Vault、授权读取范围内、已在本地可读的 `.md` 笔记；纯只读，不要求 Zotero 来源 ID、UUID 或论文属性                                |
| 存储      | 展示原文件的快照，不复制为新的知识笔记，不添加 Bridge 属性，不迁移或重命名目标文件                                                       |
| 补全      | 输入第二个 `[` 后弹出候选；继续输入按名称、路径、别名筛选；Enter/点击选择，Esc 关闭                                                      |
| 点击      | 预览中单击内部链接展开；编辑中普通点击移动光标，macOS 使用 Cmd+点击打开所在链接                                                          |
| 关联      | 递归按点击展开，不自动爬取所有链接；同一组内同一文件复用卡片并定位锚点                                                                   |
| 连线      | 浅蓝色虚线双箭头；Bridge 端连接具体双链文字，知识卡端连接标题栏左/右侧，不从顶部垂直接入；不自动写入反向链接                             |
| 生命周期  | 根卡一键收起只关闭其关联子卡和线；根卡正文、现有草稿和同步任务不受影响                                                                   |
| 两种视图  | Reader 小卡片和展开编辑窗都支持补全及关联浏览；C5-A/B 为同文档浮层，C5-C/D 扩展为按根组管理的桌面窗口与跨窗口线层                        |

| 非目标    | 编辑普通知识卡、跨 Vault、完整 Obsidian 工作区、任意第三方插件执行、自动建知识笔记、自动全库图谱；Windows/Linux 桌面连线须另立适配与验收 |

原生 Obsidian 支持 Wikilink、Markdown 内部链接、显示别名、标题与块引用；输入 `[[` 可以选择链接目标，文件夹链接可使用 Vault 内路径。C 系列以这些原生语义为兼容目标，而非发明新链接格式。参考：[Obsidian 内部链接](https://help.obsidian.md/links)。具体实现必须复核项目锁定的 Obsidian API 声明；官方声明来源：[obsidian-api](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)。

### 9A.2 交互与链接语义

1. 根卡中输入 `[[`，空查询显示最近使用及有稳定排序的有限候选，不一次渲染整个 Vault。输入 `贝叶` 后筛选；每行显示标题、必要的别名及文件夹路径，区分同名笔记。
2. 选择候选后插入规范 Wikilink。默认使用能唯一定位的 Vault 相对路径去掉 `.md`；选择别名时插入 `[[目标路径|别名]]`。不直接把别名当真实文件名。用户手写的原有短链接保持原样。
3. 支持 `[[笔记]]`、`[[目录/笔记]]`、`[[笔记|显示名]]`、`[[笔记#标题]]`、`[[笔记#^块ID]]`、`[[#当前标题]]` 和普通 Markdown 的 Vault 内文件链接。标题/块定位依据 Obsidian 缓存及匹配版本的正文位置，不自行猜 slug。
4. `[[笔记#` 提供标题候选，`[[笔记#^` 提供块候选；多层标题路径在 C2 夹具中验证。重复标题、缺失锚点不能静默跳到另一个章节，需有明确反馈或选择。
5. `![[笔记]]` 第一版只呈现可点击的嵌入引用占位，不自动递归展开全文；本地图片嵌入在白名单内渲染。代码块、行内代码、转义文本和注释中的类似双链不触发补全或展开。
6. 找不到文件时显示“未找到”，不创建文件。文件存在但锚点缺失时保留可阅读的全文并提示锚点不可定位。遇到不支持类型提供类型提示及受控的“在 Obsidian 中打开”。
7. 子卡依次点出 A → B → C；遇到 A → B → A 时聚焦已有 A，不重复创建卡片。根卡同文件链接只定位根卡；根卡尚未保存的标题/块导航优先使用当前会话正文，不为了导航强制同步。
8. 每张子卡有标题拖拽区、相对路径、只读状态、关闭、刷新及在 Obsidian 中打开的图标按钮；悬停 tooltip 和无障碍名称完整。正文可选中复制、滚动，但无编辑或保存入口。
9. 单独关闭子卡时移除该节点及其关联边，其他已打开子卡保持可用；根卡一键收起则移除整组子卡。关系是图，不使用会误删多父节点子卡的简单树形级联删除。
10. 根卡真正关闭、来源切换、Reader 销毁、切回 native 或插件停用时，销毁对应关联组并取消读取订阅；根卡先走既有草稿检查点。切换编辑/预览不销毁关联组。C5-C/D 中，聚焦本组独立知识卡不等于根卡关闭；根卡小浮窗与展开编辑器的身份、布局和关闭策略按新阶段明确管理，不能因一次 blur 销毁整组。

**只读消息契约（C1 实施时固定为类型定义与夹具）：**

- 消息头至少含 `readProtocolVersion`、`requestId`、`targetVaultId`、`pairingEpoch`、`clientSessionId`、`generation`、`operation`、`expiresAt`。版本与写协议分别管理；以能力协商决定是否发送，不提前假定版本号与写协议一致。
- 操作为 `search-notes`、`resolve-link`、`read-note`、`read-note-resource`；不含任意文件系统命令、执行代码或可写操作。所有请求/响应有运行时结构校验。
- `search-notes` 输入查询、上下文路径、上限与游标；输出有限个 `{path, basename, matchedAlias}` 与索引代次，不返回全库正文。
- `resolve-link` 输入原始链接目标及包含该链接的 `sourcePath`，由 `metadataCache.getFirstLinkpathDest(linkpath, sourcePath)` 等已核对 API 解析，返回规范相对路径与片段。子卡继续展开时上下文必须是该子卡路径，而非根文献卡路径。
- `read-note` 返回已保存 Markdown、规范路径、内容 revision、索引/缓存代次与读入时间。标题/块缓存只有在正文版本匹配时才用于定位；不一致则重读或标明定位暂不可用。
- 结果类型至少区分 `ok`、`not-found`、`anchor-not-found`、`forbidden`、`unsupported`、`too-large`、`indexing`、`offline`、`timeout`。UI 必须能区分空结果、离线及请求错误。
- `NodeKey = targetVaultId + canonicalRelativePath`；`ViewKey = windowId + rootSessionId + NodeKey`。片段决定滚动目标，不新建同一文件的重复卡。路径是会话内地址，不冒充文件永久 UUID；重命名后通过 Obsidian 事件/重新解析更新。
- C5-C/D 的 `windowId` 继续指原始根宿主身份，独立子窗另有 nativeWindowId；不能因新开 Document 改变根组归属、绕过上限或共享其他根组的窗口。配对代次另外参与注册与响应有效性检查。
- 边保存实际 `from`、`to`、链接片段及出现位置；视觉双箭头不改变引用方向。多个同目标链接合并视觉线但保留来源计数/定位信息；不写回 Markdown。

**传输选择与性能隔离：**

第一版优先延用已配对的本地文件通信根目录，但在独立 `note-query` 命名空间内做短生命周期请求/响应；不能把检索排进持久化写事务队列，也不能让旧 companion 把读取请求误认作写入。新 namespace、能力公告和清理规则必须同时升级两端。共享的是配对基础设施，不是第二套卡片写入队列。

请求原子发布，响应按请求 ID/配对代次验证；读取成功不产生写入成功 ACK。消费后清理响应，TTL 清理过期孤儿文件；重启后不恢复旧补全请求。每客户端最多 4 个并发查询，搜索采用 latest-wins 与约 120 ms 防抖；限制活跃查询轮询，不用空闲高频扫描拖慢主应用。查询消息最长 30 秒；能力公告单独采用 120 秒租约，容忍桌面应用后台定时器约 60 秒的节流，但进程关闭时仍须写入 disabled 状态。C1 必须先测实际配对目录的往返延迟；若文件通道无法满足后述目标，应提交测量再评估新的 IPC，而非隐瞒延迟或把正文复制成笔记。

### 9A.4 安全、缓存与显示边界

- 关联浏览是单独的显式启用能力。其读取范围可以覆盖同一 Vault 的知识目录，默认排除 `.obsidian`、隐藏配置、回收站和恢复备份目录，并允许设置目录白名单。开启时说明会读取笔记名称、别名及按点击读取正文；不静默继承更宽权限。
- **不得放宽现有 `outputFolder` 写入限制。** 即使只读预览可以访问 `Mathematics/`，写接口仍不能修改该目录中的普通笔记。两种权限检查分别测试。
- 普通知识笔记无需新增任何元数据。展示隐藏 frontmatter 和已识别的 Bridge 机器载荷，但不删除磁盘内容；不将任意 HTML 当可执行 DOM。
- 链接可以包含正常相对引用；解析后必须检查目标 realpath 仍在授权 Vault 内，禁止绝对路径、跨 Vault、目录逃逸和符号链接绕过。协议接受规范 Vault 相对路径，不能直接把未经校验的链接拼接到文件系统路径。
- 原始 HTML、脚本、事件属性、`javascript:`、危险 `data:` URL、iframe 不执行。图片默认只读配对 Vault 内白名单光栅格式；远程图片不自动联网，SVG 默认不执行/不加载；外部链接只由明确点击交给安全 URL 打开逻辑。
- 本地图片以目标知识卡路径为上下文解析，不能使用根批注卡目录。经只读资源接口返回受限二进制/base64 数据及 MIME/哈希；对象 URL 随卡片释放。禁止把任意用户输入的 SVG 当作连线层注入。
- 在线预览展示磁盘已保存版本，不读取 Obsidian 编辑器的未落盘缓冲区。提供刷新，外部保存/重命名/删除触发版本失效；不因刷新抢走用户的滚动位置或焦点。
- 第一版缓存仅限进程内内存，按 Vault 身份、配对代次、路径和 revision 分区；只缓存已经请求的正文及资源，不预取全库。关闭关联组保留有限 LRU 缓存供短期离线浏览；重启后无缓存则明确不可用。
- 配对切换、功能停用和读取权限收紧时立即清空相关缓存与对象 URL；收到删除通知后不再把旧缓存当在线现存文件。离线时无法确认删除，展示“缓存，可能过期”和读入时间。
- 建议初始上限：每组 8 张子卡、每窗口 16 张子卡、单正文 2 MiB、单图片 5 MiB、每笔记/响应累计资源 10 MiB、总缓存 32 MiB；超过上限明确拒绝或保留原卡，不静默截断正文为完整结果。长文可渐进渲染并标明尚未展示部分。
- 查询参数设长度、候选条数、资源数量和 TTL 上限；本地配对不是对同一操作系统账户下恶意程序的强安全边界。不得宣称 Vault ID 本身就是鉴权密钥，不记录正文、搜索词或完整私人路径到默认日志。

### C1：配对只读服务、索引与异步传输

**目标：** Zotero 可以安全查询和读取普通知识笔记，且不影响 B5 的保存队列。

**工具/位置：** TypeScript、Obsidian 公共 Vault/MetadataCache API、Node 文件系统测试、两端协议校验、现有 companion 配对/心跳、拟新增 note-query 模块。

**执行步骤：**

1. 核对锁定版本 API，定义 9A.3 的消息、能力与错误枚举；读取服务单独启用，权限设置变更必须失效旧请求和缓存。
2. companion 完成布局/索引初始化后构建轻量名称/路径/别名索引，监听创建、修改、删除、重命名和元数据变更并增量更新；不在每次输入时遍历/读取全库正文。
3. 实现搜索、解析、正文与图片四类只读处理器，使用结构化解析器读取 frontmatter/元数据；以源路径调用 Obsidian 链接解析接口。服务返回的路径再次受权限约束。
4. 实现独立异步消息命名空间、版本/配对代次校验、限流、latest-wins、超时、取消与 TTL；能力租约与单次查询时限分开，覆盖后台计时器节流；关闭 UI 后的迟到结果只能清理，不能创建卡片或改变编辑器。
5. 在写队列处于占用等待/离线时同时发起检索，确认读取不等待写队列排空；旧 companion 无能力时立即提示升级或使用已有缓存，不反复提交未知请求。

**验收/交付：** C1-01 四类接口正常/错误用例均有测试；C1-02 错 Vault、旧配对代次、越界路径与损坏请求全部拒绝；C1-03 搜索不会写笔记，原 `outputFolder` 限制不变；C1-04 连续 100 次取消/超时后请求文件和在途数在 TTL 内清理；C1-05 1 万笔记夹具只建立一次初始索引，后续更新增量完成并记录往返时间。产出协议文档、测试和 C1 报告。

### C2：链接解析、目标定位与 Markdown 接入

**目标：** 识别用户原有 Obsidian 链接，确定目标及锚点，避免错误链接与错误文件关联。

**工具/位置：** markdown-it token/ruler、CodeMirror 语法/文档位置、`note-links.ts`、Obsidian `getFirstLinkpathDest`/缓存位置、单元夹具。

**执行步骤：**

1. 为 9A.2 列出的普通双链、别名、标题、块、当前文件、Markdown 链接和嵌入占位建立解析夹具；保留原始源区间，不能依靠渲染后 HTML 反推源文。
2. 在 markdown-it 中添加安全 token 渲染，内部链接使用受控属性传递目标，显示文本转义；外链继续走现有安全分支。不得把双链插件应用于代码/转义区域。
3. 同名文件按 Obsidian 解析结果处理，候选选择使用明确路径；别名显示与真实目标分开存储。不自己发明大小写/Unicode 折叠规则来猜另一个文件。
4. 标题和块根据匹配 revision 的正文/元数据定位；多层标题、重复标题、块不存在和索引滞后分别处理。子卡的相对链接、图片和当前笔记锚点使用子卡自身上下文。
5. 接入预览点击与编辑模式 Cmd+点击。Reader textarea 通过点击后的光标位置和 token 范围确认链接；CodeMirror 使用文档位置/装饰。无法确认目标时不猜测，也不抢走普通文字选择。

**验收/交付：** C2-01 所有支持语法与原生 Obsidian 在夹具集上解析一致；C2-02 代码/注释/转义不触发；C2-03 缺失文件不自动创建，缺失锚点不假装成功；C2-04 根→子→孙的相对路径定位正确；C2-05 手工输入不因渲染被重写，点击导航不触发保存。产出链接支持表、解析模块、单元测试及 C2 报告。

### C3：两种编辑器的双链候选补全

**目标：** 在 Zotero 中输入双链时不必记忆完整文件名，且中文输入与既有保存行为不受影响。

**工具/位置：** 共用补全控制器、Reader textarea adapter、CodeMirror 6 completion API、Fluent、真实 macOS 输入法；优先复用已安装 CodeMirror 依赖，新增直接依赖时更新锁文件与许可审计。

**执行步骤：**

1. 在第二个 `[` 输入后打开候选，自动补齐 `]]` 时保留中间光标。避免插入第二套闭合括号；空查询只展示最近/前 20 个候选。
2. 实现约 120 ms 防抖、最多 20 条可见结果、分页、请求代次与加载/空结果/离线/失败状态。筛选名称、路径和别名，不做未经同意的全文搜索。
3. 候选行突出匹配文字并展示路径；上下方向键、Enter、点击、Esc 行为一致，候选弹层锚定光标且不被卡片滚动/裁切遮挡。
4. 仅替换当前链接 token 范围，保留周围正文、选区和撤销历史。CodeMirror 使用单个 transaction；textarea 采用与现有输入同步兼容的范围替换并验证 Undo，禁止重设整篇 value 破坏历史。
5. 输入 `#` / `#^` 切换标题/块候选；输入 `|` 后作为显示文字编辑，不能把别名覆盖回用户手写内容。光标移出链接、闭合链接或切卡时取消旧查询。
6. 中文 composition 期间不提交候选、不插入链接，不把 Enter 从输入法抢走；组合完成后再检索。Escape 优先关闭候选，不关闭根卡；Backspace/Delete 不向 Zotero 批注删除快捷键泄漏。

**验收/交付：** C3-01 小浮窗/大编辑窗全部流程通过；C3-02 中文、空格路径、同名和别名选择结果可被 Obsidian 解析；C3-03 连续 50 次查询乱序/切卡零串结果；C3-04 一次插入可一次 Undo/Redo，组合输入零吞字/重复字；C3-05 保存队列繁忙时仍可输入和检索。产出补全 UI、双语文案、组件与真实宿主证据。

### C4：普通知识笔记只读渲染

**目标：** 把没有 Bridge 元数据的普通笔记显示为安全、可导航的知识卡。

**工具/位置：** 现有 markdown-it/KaTeX、`card-markdown-preview.ts` 中可复用资源逻辑、拟新增通用只读 renderer、XHTML/Gecko 与 Obsidian 对照夹具。

**执行步骤：**

1. 建立 `loading / ready / cached / stale / not-found / forbidden / unsupported / error` 状态，不借用根卡保存状态。显示真实笔记标题、路径、只读标记和缓存时间。
2. 读取全笔记已保存 Markdown，隐藏仅展示层的 frontmatter 和已识别机器载荷；不能使用只提取 My notes 的批注卡函数误截普通正文。
3. 复用安全渲染及 XML/XHTML fragment 导入修复，支持标题、列表、表格、任务列表（只读）、代码、公式、链接和白名单本地图片。任务勾选等渲染控件不得产生写入。
4. 对目标标题/块滚动并短暂标记位置；缺失片段有明确提示。正文内部链接继续交给关联组控制器，外链由用户点击打开。
5. “刷新”重新验证 revision，变更后保留合理的滚动锚点；“在 Obsidian 中打开”使用已验证 Vault/文件路径，不能在目标缺失时意外创建同名文件。
6. 超大正文/图片明确提示，渲染重任务可取消；关闭卡片释放对象 URL 和监听器。远程资源、第三方动态块显示安全占位，不执行。

**验收/交付：** C4-01 无 Zotero 信息的普通知识卡可正确展示；C4-02 标题/公式/代码/图片在 Reader 与展开窗均无空白、重复公式或 XML 错误；C4-03 每轮浏览前后目标文件哈希一致且零普通笔记写请求；C4-04 危险内容不执行、不产生隐式远程请求；C4-05 点击子卡双链可继续解析。产出渲染支持表、截图和 C4 报告。

### C5：多卡片、拖拽缩放与关系连线

**目标：** 建立可递归展开、可移动、可统一管理的关联卡组。C5-A/B 采用同文档浮层作为已实现基线；C5-C/D 在保留图模型、只读边界及锚点规则的前提下，扩展为桌面独立窗口和跨窗口连线，不把多个无归属的系统弹窗视为完成。

**工具/位置：** `LinkedCardGraph`、`KnowledgeCardGroupSurface`、CSS 定位/尺寸约束、Pointer Events、SVG、ResizeObserver、requestAnimationFrame、现有受管理面板挂载/定位函数。

**执行步骤：**

1. 每个根卡建立独立组和同 Document 浮层，置于可见工作区而非被原生 popup overflow 裁切的内部容器。背景层 `pointer-events: none`，只有卡片和必要控件接收指针；不遮断 PDF 操作。
2. 首次打开优先放在来源卡旁边，空间不足则换侧/错位；卡片整体受视口约束。初始建议尺寸 360×300 CSS px，最小 260×180，实际最小值不得超过可用工作区；小视口改为可滚动单列而非产生 min/max 冲突。
3. 仅标题栏拖动，正文区域用于选择/滚动；使用 Pointer Capture，处理 pointercancel、失焦、跨边界与缩放。缩放到最小边界后可立即反向放大，不能卡住或出现负尺寸。
4. 为卡片提供稳定 z-order、焦点恢复、关闭和键盘可达的布局重置；打开同一目标时聚焦已有卡，不叠出第二份。标题/路径长文本截断或换行，控件不被挤出。
5. 同文档 SVG 线层置于知识卡片下方；Bridge 端点绑定对应双链文字，知识卡端点绑定标题栏左/右侧。移动、缩放、viewport resize 时按帧合并更新几何，不重渲染 Markdown；端点/箭头不盖住标题按钮。桌面后端的跨窗口层级按 C5-D 单独验证。
6. 使用浅蓝虚线双箭头与短暂淡入效果；真实引用方向保留在模型及 tooltip 中。支持 reduced-motion，默认不运行永久流动动画，静止状态不持续触发几何循环。
7. 根卡添加小型“收起关联卡”图标和 tooltip。优先复用现有图标库，新增时采用 Lucide；不手绘常规按钮 SVG。清理整组节点/边/未完成查询，但不取消根卡保存或删除链接。
8. 多 Reader、根卡 A/B 切换、展开窗分别按组隔离；使用 generation 拒绝旧响应。处理多父引用、循环、自引用、达到卡数上限、关闭中间节点后再次打开等图状态。
9. C5-A 为每个规范 `(sourcePath, targetPath)` 关系维护自己的可见链接锚点；切换或点击另一条链接不覆盖现有来源位置。若链接隐藏/被裁切，回退到其所属源卡标题，不借用最近点击位置。
10. C5-B 在卡组内容或成员变化后有界并发地扫描根卡和已打开卡片的链接，仅解析关系；只把两端都属于当前可见卡组的关系自动画出。不得为了发现关系自动打开第三张卡、读未打开正文、写笔记或占用保存/ACK 队列；旧内容代次和已撤销权限的响应不得生效。

**验收/交付：** C5-01 A→B→C、A→B→A、自引用、菱形引用正确且无重复节点；C5-02 所有卡可拖拽/缩放，最小边界来回 20 次无卡死；C5-03 一键收起只清理当前根卡组，根卡正文及队列不变；C5-04 至少两独立 Reader 与展开窗零跨组连线/串卡；C5-05 线端点随动、无按钮遮挡，点击空白不吞 PDF 操作；C5-06 达上限后聚焦已有卡仍可用，未创建不可见孤儿节点；C5-A 不同关系的来源锚点在交叉导航后稳定；C5-B 新卡出现后无需再点其反向/根卡链接即可发现当前卡组成员间的关系，且不自动加载额外卡片。产出卡组模型、UI、连线与布局回归。A/B 的历次异常、后续 Reader 正文锚点修复与现场复验见补充报告；旧失败记录不等于当前包仍失败，定向通过也不等于完整矩阵已通过。

### C5-C：桌面独立知识卡窗口

**状态：开发中，原型部分宿主验证。** C5-C 尚未形成正式桌面能力；现有 C5-A/B 同文档卡片与连线仍是可用基线，不删除其安全回退路径，也不以脚本改坐标冒充鼠标拖出窗口。

**执行：** 原 DOM 父子关系不能再代表整组归属。以注册表识别“焦点转入本组知识窗”，在该动作中保持 Reader 根卡和 EditorSession；真正点击外部关闭、切换批注、关闭 Reader/展开窗、切 native 与停用插件仍按明确策略收组。原生 popup 若不可可靠保留，应在受控适配器内建立由同一会话持有的根 Bridge 视图；不得全局改写 Reader 外部点击、批注删除或原生评论保存方法。

**核验：** 在根卡及两知识窗之间往返聚焦 50 次，Reader 根卡不意外关闭；点击子卡关闭只移除对应卡及关系，根卡及其他用户已打开卡保持。知识窗正文仍可选中/复制/滚动；Cmd+W 只关闭当前知识窗，Esc 按当前菜单/窗口规则处理，Backspace/Delete 不向 Reader 泄漏。回根卡验证 Enter、中文 IME、Undo/Redo、补全与草稿无退化，不能只做模拟键盘测试。

**输出：** 根卡/子卡激活与关闭策略、真实键鼠证据；若无法保留根来源且不能安全适配，此项 FAIL，不以“子窗打开成功”签收。

#### C5-C.6 实现桌面布局、系统拖动与屏幕恢复

**执行：** 优先使用宿主原生标题栏拖动与缩放，保留自定义卡片标题/操作区；若使用无边框自定义拖动，必须验证系统拖动循环和移出原窗口后的事件连续性。卡片不再按父 `innerWidth/innerHeight` 夹紧，只按显示器可用区域维护可找回的标题与最小尺寸。多屏布局不能只用所有屏幕外接矩形，否则会把卡片放到不存在的屏幕缝隙。

**核验：** 从 Reader 和展开窗分别把卡移到父窗四边之外，再移到第二块屏幕；拖动/缩放最小边界往返 20 次。验证负坐标、菜单栏/Dock 安全区域、改变分辨率/缩放、拔掉外屏和唤醒。每组提供图标式“整理/找回窗口”入口及 tooltip，恢复后至少标题和关闭按钮可达；不能恢复成极小尺寸或在屏幕外无入口。AppKit 的 [NSScreen.visibleFrame](https://developer.apple.com/documentation/appkit/nsscreen/visibleframe) 可作为原生后端可用屏幕区域的依据，区域随系统界面设置变化，不能只在启动时缓存一次。

**输出：** 桌面布局函数、显示器拓扑失效策略与实测矩形。第一版布局仅驻内存；如要跨重启持久化，另定无正文/无私密绝对路径的存储与迁移规则，不混入笔记文件。

#### C5-C.7 接入真实只读内容与后端切换

**输出：** 双语设置/图标、受控交接测试及真实数学/物理知识卡演练；不新建“独立 Markdown 副本”。

#### C5-D.2 建立唯一桌面坐标服务

**执行：** 明确区分 Reader iframe 的 CSS 像素、顶层内容区、原生窗口 frame、桌面逻辑坐标和屏幕 backing 像素。内部统一为带显示器拓扑代次的桌面逻辑坐标：参考显示器左上为原点、y 向下、允许负坐标；AppKit 原生方向/单位在边界转换，不能把 DOMRect 直接当原生屏幕点。

**执行：** 通过实际窗口 API/受控几何桥获取内容区原点与缩放，处理 iframe 嵌套、父 transform、Reader 文档缩放、系统标题栏和显示器 backing scale。禁止只用 `screenX + rect.left`，也不能全局乘一次 `devicePixelRatio`。每窗口维护经过校验的变换、窗口代次和观测时间；拖到另一屏幕、缩放或拓扑变化时重新计算。原生后端可参考 [NSWindow.convertPoint(toScreen:)](https://developer.apple.com/documentation/appkit/nswindow/convertpoint%28toscreen%3A%29) 的窗口到屏幕转换语义，但 DOM 到原生内容区的变换仍必须单独核验。

**核验：** 合成坐标覆盖窗口四角、内容区四角、标题栏、负坐标、1×/2×及不同缩放屏幕、上下/左右屏幕布局和 iframe transform。真实用已知可见标记与屏幕点互相校准；静止端点误差初始要求不超过 4 个屏幕逻辑点。变换失效时隐藏相应边并重新校准，不画到另一个笔记或屏幕位置。

**输出：** `DesktopGeometry` 纯函数与真实校准报告；窗口移动与屏幕坐标换算使用同一服务，禁止各视图自行拼公式。

#### C5-D.3 桌面根锚点与关系绑定不回退

**执行：** 沿用 C5-A 每条关系独立的锚点选择：显式点击的链接出现序号优先，自动补关系按已确认规则选具体路径。把根卡当前可见链接 DOMRect 转为桌面矩形，保留 `(groupId, from, to, occurrence, contentGeneration)`，DOM 重绘后重新定位；知识卡端点取其原生窗口标题区域的左右侧边。

**核验：** P02N01 同时含 `[[bay]]`、`[[Mathematics/Bayes]]`、`[[Physics/Motion]]`；先开 Bayes，再从 Bayes 开 Motion，自动补足根卡与 Motion 关系，Bayes 不跳到 Motion 行。交换卡片左右位置、滚动根卡、编辑/预览切换及标题/正文重绘后复验。保留已修复的“祖先 hidden、后代显式 visible”Reader 条件，不能重新误判可见性。

**异常策略：** 源链接滚出视口/真正隐藏时，不借用另一链接；仅当所属根卡标题仍实际可见时可回退到该标题，并记录暂不可定位状态。根来源窗口最小化、隐藏、切离 Space 或几何不可信时隐藏对应根边；根来源真正关闭则收组。根卡可见时必须恢复到具体链接文字，不能永久留在标题栏。

**输出：** 桌面锚点集成测试与真实根卡/知识卡端点标注证据；语义扫描继续只读解析已打开成员，不因桌面后端自动加载额外笔记。

#### C5-D.4 实现不挡输入的透明绘制层

**执行：** 每个运行实例在每个使用中的显示器至多一个透明线层，窗口不接键盘焦点、不显示实体白底/边框/阴影、不成为 Cmd+W 目标。共享线层按 groupId 隔离路径贡献与引用计数：关闭一组只删该组的线，最后一组退出才销毁空线层；不同 profile 实例不共享内容或窗口句柄。线条可以使用安全生成的 SVG/Canvas 或原生路径，但原生窗口必须真正忽略鼠标；不以 CSS hit-test、不透明大窗或不断转发全局鼠标事件替代。先启用系统级穿透，再显示覆盖层；任何握手失败立即隐藏/销毁，不允许短暂出现整屏输入屏障。

**核验：** 连接同屏窗口及跨显示器窗口。优先全局算一条连续曲线，再按各显示器实际区域裁切，不能每屏分别生成不同形状；箭头只出现在实际端点，不在屏幕接缝重复生成。检查屏幕缝隙、菜单栏/Dock、分辨率变化和显示器断开后的线层数量。打开任何正常菜单/对话框时不抢焦点、不阻挡输入。

**输出：** 线层后端、权限/平台能力检测及可一键关闭桌面显示的故障入口；UI 仅用简洁图标/模式标签和 tooltip，不添加常驻教学文本。

#### C5-D.5 保留侧面双箭头并实现知识卡避障

**执行：** 将已验收的左右侧边端点和切线方向设为不可退化约束，`marker-start`/`marker-end` 或等价原生箭头在两端都可见。根卡到知识卡仍从具体双链文字出发，允许经过根卡自身正文，不为“绕根卡”而把端点改到标题。知识卡与知识卡只从标题栏左/右侧连接，不切换成顶部端点。

**执行：** 独立路由层使用完整知识窗矩形及间距作为障碍，包含源/目标自身及其他已打开知识窗；先保留现有无冲突曲线，发生相交才选择外侧绕行/中间航点并平滑。上下叠放、近同列、左右反向及第三卡挡路各有用例；同组双向引用只画一条双箭头，真实方向留在模型。几何重叠导致不存在完全可见路径时，保留侧边端点并采用已定义的部分可见/需整理状态，不承诺数学上不可能的“完全重合卡仍全线可见”。

**核验：** 用曲线采样或曲线/矩形相交测试验证可解布局下不穿过知识卡正文；目视检查箭头未被边框/遮罩裁掉且不盖按钮。新增回归必须保护 C5-A/B 已通过的具体正文行锚点、侧边双箭头和上下知识卡绕线，不能修一类后让另外两类退化。

**输出：** 有界耗时的路由器、固定布局截图及路径几何断言；拖动只更新几何，不重渲染 Markdown、不发只读查询。

#### C5-D.6 协调层级、可见性和系统窗口管理

**执行：** 线层要能画出 Zotero 父窗外的线，也要看得到根卡正文端的箭头；不能把线层简单压到整个 Zotero 窗口后面。优先验证“根窗之上、知识卡之下”的可控次序；若平台不保证该次序，评估在线层按本组知识卡矩形裁切/遮罩，使线不覆盖卡内容。两种路线都必须保留根卡内部的实际文字锚点。不得把其他应用的窗口内容抓屏拿来计算遮挡。

**核验：** 根卡、子窗、菜单、模态对话框、另一个 Reader 和其他应用依次切前台，检查线没有盖住按钮、穿过知识卡正文或留在错误前台。桌面模式不因换一次焦点就把所有卡抢到最前；默认策略下本组退后台时线与卡协调退场。若用户选择跨应用置顶，另测置顶卡的正常输入、应用切换和一键取消，不提升到系统安全窗口之上。

**核验：** 最小化/恢复、隐藏 Zotero、Spaces 切换、全屏、Stage Manager、Mission Control、锁屏/解锁和睡眠/唤醒分别执行；若来源/目标不在同一可见桌面，不画跨不可见桌面的伪连线。恢复时先确认窗口和锚点几何再显示线，不使用休眠前的陈旧端点。

**输出：** 精确系统支持表及每项预期/实际。原生窗口管理策略参考 [NSWindow.CollectionBehavior](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct)，不能把加入所有 Spaces、全屏辅助与 Stage Manager 行为当同一个开关。自动隐藏是保安全的行为，不能用它掩盖当前声明支持场景下应显示却不显示的失败。

#### C5-D.7 随动、帧合并与性能治理

**执行：** 优先订阅本应用窗口 move/resize、屏幕拓扑、根文档 scroll/resize 和预览重绘，按帧合并几何快照。原生拖动循环可能延迟普通脚本计时器，须在 C5-D.1 实测后选择能在拖动中运行的通知/调度机制。只在发生变化或有效拖动时刷新；静止后不永久运行 60 Hz 几何轮询，不发送逐帧文件 IPC。几何有效性按窗口/拓扑代次和存活状态判断，不把“静止未更新”误判为端点过期；可选的低频存活心跳与布局/绘制循环分开。

**核验：** 1/3/8 子卡与两个独立组分别采样，根窗与子窗单独或连续移动、快速缩放及跨屏时都无长时间冻结。初始目标：8 子卡几何/绘线帧耗时 p95 ≤ 32 ms，观测位置到可见线更新 p95 ≤ 50 ms，静止端点误差 ≤ 4 个屏幕逻辑点；每类至少 100 次或足够覆盖拖动的连续帧，记录测量方法而非凭“丝滑”判断。拖动中误差与停止后收敛分别报告。

**核验：** 静止 60 秒的线重绘计数在布局稳定后不持续增长；相对相同开卡数但无线层的空闲 CPU 基线，持续额外占用超过 1 个百分点需调查。根卡输入/保存 p95 相比同环境基线退化超过 20% 必须调查；任何持续同步阻塞、光标回跳或 IME 吞字均直接 FAIL，不用平均性能掩盖。

**输出：** 窗口事件/布局/绘线的独立计时、空闲/拖动 CPU 与资源记录；阈值调整须说明硬件和测量依据并提前更新验收约定。

#### C5-D.8 故障、安全、可选原生辅助组件与包核验

**执行：** 窗口注册、屏幕拓扑、根来源、内容、配对和权限各自有代次；晚到几何/ready/读取响应不得复活已关闭窗口。线层崩溃、几何过期、根进程退出或可选辅助进程失联时先移除覆盖层，再受控降级；根卡本地草稿和已持久化写请求继续由 B5 负责。紧急关闭不得按进程名杀掉所有 Zotero。

**可选辅助组件边界：** 仅在原型证实需要且用户确认后引入；优先只负责显示器几何和画线，接收受限窗口/边 ID、矩形、路径及可见状态，不接收 Vault token、正文或文件系统读写命令。采用系统支持的受控本地 IPC，并验证对端身份、每次启动会话秘密、版本、长度和代次；不开放无鉴权网络端口。若需由辅助组件托管卡片正文或提升权限，必须重新设计数据/渲染信任边界并单独评审，不能沿用“只传几何”的安全结论。

**包核验：** 新增原生二进制时列出 arm64/x86_64 支持、可复现构建、许可、第三方声明、签名/公证及分发更新方案。无签名/仅本机开发产物可以用于明确授权的隔离原型，不能当正式发布包。辅助组件与插件版本不匹配时拒绝桌面模式，原窗口内模式仍可用；更新/卸载清理只针对本项目受控产物。

**核验：** 注入失联、崩溃、重复消息、假窗口 ID、错组/错配对代次、非有限/超限坐标、显示器丢失、开窗中停用及重启。覆盖层失联的隐藏/退出目标 ≤ 2 秒，且从未拦截下层输入；若平台无法保证安全撤场，此实现路线不通过。日志不记录正文、搜索词或私人绝对路径，不隐式联网、不增加全局按键采集。

**输出：** 威胁边界、故障恢复表、精确 XPI/可选组件哈希和安装回退步骤。安全与包核验是桌面正式集成的必需条件，不因“只画线”豁免。

### C6：离线缓存、权限失效与资源回收

**目标：** 关联浏览可安全降级，不拖慢编辑、不泄漏越界正文、不留下无限增长的后台资源。

## 11. B7：输入体验、兼容性与性能

**目标：** 长时间阅读编辑可用，不干扰 Zotero，也不会因浮窗重建不断增加后台任务。

**工具：** 真实中文输入法、Zotero profiler/开发工具、macOS Activity Monitor、结构化计时日志、可选浏览器组件截图测试。

### 执行操作

1. 核对本机现有简体中文输入法，优先使用用户已安装的输入法；不能因当前键盘布局为 ABC 就认定系统没有中文输入法。
2. 测试拼音组合、候选选择、回车、撤销/重做、粘贴、切预览和组合期间关闭/切换批注；记录预期提交或恢复行为。
3. 测试主窗口、独立 Reader、多个 PDF 标签、分栏、不同缩放/旋转、侧栏开关、明暗主题与放大字号。
4. 重复开关浮窗 100 次、快速 A/B 切换 50 次、连续编辑至少 30 分钟；统计会话、DOM 容器、观察器、计时器、在途任务与内存。
5. 在指定机器/版本、空闲本地目标和固定夹具条件下采样至少 100 次；分别记录卡片壳、已有正文加载、预览和同步完成的 p50/p95，不能把目标忙碌的等待混入 UI 渲染性能。
6. 组件可用 Playwright 等做截图与事件测试，但真实 Zotero 的 Gecko/iframe/IME 行为必须由宿主验收，不以 Chromium 模拟通过代替。
7. 纳入 C 系列上限卡组、候选搜索、虚线拖动、缓存与只读请求，分别测量关闭/启用关联浏览时的输入、预览、根卡保存及内存基线；C7 的短期验收不能替代本阶段 30 分钟真实编辑。

### 拟定验收指标

下列耗时是**工程目标，尚未测得**；如真实宿主限制导致无法达到，应提交测量与调整理由，不能事后无说明地降低阈值。

| 指标                           | 目标                                                               |
| ------------------------------ | ------------------------------------------------------------------ |
| 热启动浮窗卡片壳出现           | p95 ≤ 200 ms                                                       |
| 本地空闲、已有卡片的正文可编辑 | p95 ≤ 500 ms；首次建卡/网络云盘等待单列                            |
| 1 万字符夹具预览刷新           | p95 ≤ 200 ms，不打断输入                                           |
| 10 万字符输入                  | 可编辑，可采用延迟/手动预览，不冻结宿主；记录具体性能              |
| 100 次开关后资源               | 自有容器/监听器/计时器回到规定基线；无同源重复会话/保存任务        |
| 30 分钟编辑                    | 无正文丢失、无跨卡写入、无持续累积的任务；内存曲线可复核           |
| 相同环境回归                   | 关键耗时/稳定内存较基线退化超过 20% 必须调查，不能直接忽略         |
| 交互与布局                     | 中文输入不重复、不吞已提交文字；主要控件可达，无覆盖正文的异常布局 |

交付：支持版本表、输入法记录、性能基线、资源清理结果与已知限制。没有实测的平台/版本不得写成已支持。

## 14. 实际开发的通用执行流程

### 14.1 每阶段循环

1. 读取上一阶段退出条件与未解决问题，检查 Git 差异、当前测试路径和应用进程身份。
