# C5 执行报告：关联知识卡组

日期：2026-11-06，C5-A/B 补测更新于 2026-11-07
状态：**C5 核心及 A/B 开发完成；自动化回归通过；A/B 的隔离展开编辑器三卡场景通过。Reader 原位弹窗本次仍显示原生评论框；完整宿主矩阵仍有未测项。**
范围：只读 Obsidian 知识卡的递归打开、卡片组管理、拖拽/缩放、连线和收起。本报告不代表 C0-C4、B4/B5 或 C 系列整体验收完成。

## 结果摘要

C5 将 Markdown 正文中的 Obsidian 内链转换为只读知识卡。每个 Reader/编辑器实例拥有自己的关联卡组；组内按 Vault 规范路径复用节点，保留有向关系并绘制浅蓝色虚线双箭头。卡片可以独立拖动和缩放，根卡可以一次收起它拥有的关联卡，不修改根批注正文或队列状态。

真实 Reader 回归曾发现一个宿主生命周期缺陷：点击子卡的关闭按钮会连根 Bridge 批注浮窗一起关闭。原因是子卡和连线层被挂在 Reader 弹窗所有者之外，Reader 将它们视为外部点击。修复后关联层挂入相同的 Bridge 所有者 DOM 层级，并沿用现有的受管理面板挂载/定位与清理机制。最终候选包已在 C 隔离 Zotero 验证：关闭子卡后子卡消失，根 Reader Bridge 卡仍打开，根卡内容及“已保存”状态保持不变。

## 实现

- `src/core/linked-card-group.ts`：有向图、节点/边去重、从根可达性计算、组/窗口数量上限，以及初始位置、拖动、缩放和视口边界夹紧。边界会随可用视口调整，缩到最小值后可以反向放大。
- `src/services/knowledge-note-card.ts`：只读卡实例和异步读取状态；每卡独立查询、代次和取消控制；以解析后的规范路径复用卡片，避免别名或重复链接产生重复节点；支持循环、自引用、共享目标、缺失/受限/过期/离线等状态及可达节点回收。
- `src/services/knowledge-card-group-surface.ts`：每个 owner 独立的浮层、卡片定位、z-order、拖动/缩放指针处理、SVG 连线、根卡锚点跟随、折叠按钮和资源清理。浮层采用 `attachOwnedNotePanel` 挂入 owner 的 DOM 层级，避免子卡关闭事件被 Reader 误判成关闭根浮窗。
- Reader 弹窗、待同步弹窗和展开编辑器接入同一只读卡组；卡片仍通过只读 note-query 能力读取，不获得普通 Obsidian 笔记写权限。
- 新增自动回归命令：`npm run test:c5-linked-card-group`。
